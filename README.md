# Зміна — Firebase-версія калькулятора зарплати 4/2

Це оновлення існуючого сайту. Оригінальне оформлення, календар 4/2, заробіток, каса, місячний план, виплати 10/25 числа та премія 2 000 ₴ із виплатою 15-го числа наступного місяця **збережені**.

## Що додано

- **`auth.html`** — сторінка реєстрації / входу по email і паролю, відновлення пароля через електронну пошту.
- **Firebase Authentication** — реальні персональні акаунти. Паролі не зберігаються у вашому коді або Firestore.
- **Cloud Firestore** — онлайн-збереження та синхронізація календаря, каси, планів, сум зарплати й налаштувань графіка на різних пристроях за акаунтом. Потрібен інтернет та коректні налаштування Firebase.
- **`admin.html`** — захищена адмінпанель: список користувачів, пошук, перегляд каси/зарплати/плану за місяцями, таблиця змін, експорт JSON. Адміністратор може **призупиняти синхронізацію** акаунта або відновлювати її. Це **не** повне вимкнення Firebase Authentication і не видалення акаунта; повне блокування/видалення потрібно робити у Firebase Console або через привілейований Admin SDK.
- **Безпека Firestore** — власник може читати і змінювати власні календарні дані; адміністратор може читати записи всіх користувачів. Адміністратор визначається **Firebase Custom Claim `admin=true`**, а не змінним полем клієнта.
- **Перенесення старих записів** — при першому вході у порожній акаунт можна підтвердити імпорт із колишнього `localStorage`. Також доступний імпорт JSON. Під час нового входу старий локальний стан не переписує автоматично вже існуючі хмарні дані.
- **Проміжна локальна копія** — під час запису в Firebase зберігається кеш поточного акаунта. Після невдалої синхронізації під час наступного відкриття можна вибрати відновлення цієї копії. Це не замінює повноцінної офлайн-синхронізації; для гарантії збереження перевіряйте статус «Збережено у Firebase» і робіть JSON-копії.

## 1. Створіть Firebase-проєкт

1. Відкрийте https://console.firebase.google.com/ та створіть проєкт.
2. У **Project settings → Your apps** зареєструйте **Web app (</>)** та скопіюйте конфігурацію `firebaseConfig`.
3. У **Authentication → Sign-in method** увімкніть провайдер **Email/Password**.
4. У **Firestore Database** створіть базу даних. Оберіть регіон і **не** залишайте безстроково тестові правила доступу.
5. Відкрийте `public/firebase-config.js` і вставте `apiKey`, `authDomain`, `projectId`, `appId` (а за потреби `storageBucket`, `messagingSenderId`). Приклад:

```js
window.ZMINA_FIREBASE_CONFIG = {
  apiKey: "YOUR_API_KEY",
  authDomain: "YOUR_PROJECT_ID.firebaseapp.com",
  projectId: "YOUR_PROJECT_ID",
  appId: "YOUR_APP_ID"
};
```

**Ці параметри вебзастосунку не є секретним ключем.** Але ніколи не додавайте в сайт **service-account JSON**, приватний ключ Admin SDK або пароль адміністратора.

## 2. Опублікуйте сайт і правила Firestore

Потрібен Node.js та Firebase CLI (інсталяція: `npm install -g firebase-tools`). У папці проєкту виконайте:

```bash
firebase login
firebase deploy --project YOUR_PROJECT_ID --only hosting,firestore:rules
```

Клієнтські файли розміщені в `public/` (лише вони публікуються); `firebase.json` вказує на папку `public` як `hosting.public` та включає `firestore.rules`.

Сайт буде доступний за адресою `https://YOUR_PROJECT_ID.web.app`. Відкрийте `auth.html` та зареєструйте перший акаунт. Якщо використовуєте власний домен, додайте його до **Authentication → Settings → Authorized domains**.

Для локального тестування використовуйте локальний HTTP-сервер (не відкривайте `file://`):

```bash
python -m http.server 8000 --directory public
```

Після цього відкрийте `http://localhost:8000/auth.html`. Для Firebase Auth `localhost` може потребувати ручного додавання до дозволених доменів. Потрібне підключення до інтернету, бо JS Firebase завантажується з Google CDN.

## 3. Призначте адміністратора

**Не можна робити першого користувача адміністратором автоматично:** тоді будь-хто, хто зареєструється першим, дістане доступ до чужих даних. Призначайте адміністратора лише у довіреному середовищі через Admin SDK.

1. Зареєструйте свій акаунт звичайним способом.
2. У Firebase Console → Project settings → Service accounts створіть приватний ключ для Admin SDK. **Не кладіть його в папку сайту, не завантажуйте у хостинг і нікому не надсилайте.**
3. На власному комп'ютері задайте змінну середовища `GOOGLE_APPLICATION_CREDENTIALS`, яка вказує на шлях до приватного JSON **поза** папкою проєкту.
4. У папці проєкту встановіть пакет, запустіть скрипт:

```bash
npm install
npm run grant-admin -- admin@example.com
```

5. Вийдіть і знову зайдіть на сайт. З’явиться пункт **«Адмінпанель»**. Пряме посилання: `https://YOUR_PROJECT_ID.web.app/admin.html`.

Якщо на вашому комп'ютері немає доступу до сервісного акаунта, призначити роль можна в іншому довіреному серверному середовищі з Firebase Admin SDK. Однакова адреса чи назва акаунта не надають адміндоступ.

## Структура даних у Firestore

```text
users/{uid}                       — email, displayName, suspended, createdAt
users/{uid}/data/calendar         — version, anchorDate, anchorPosition, days, cash, plans, updatedAt
```

`days` — зарплата, примітки та статуси за датами; `cash` — щоденна каса; `plans` — план за місяцями. Суми зберігаються в цілих копійках. Дані кожного акаунта відокремлені. Правила в `firestore.rules` — обов'язкова частина розгортання.

**Технічні обмеження:** поточна реалізація зберігає календар користувача одним документом Firestore (стандартне обмеження документа — 1 МіБ). Для великої багаторічної історії, інтенсивного одночасного редагування з кількох пристроїв або масштабування слід перейти на окремі документи за місяцями. Якщо одночасно редагувати записи на двох пристроях, пізніший запис у Firestore може замінити попередній — уникайте такого режиму.

## Розрахунки (без змін)

- Графік: чотири робочі, два вихідні, безперервний цикл через місяці.
- Заробіток з 1 по 15: виплата 25-го поточного місяця.
- Заробіток з 16 до кінця: виплата 10-го наступного місяця.
- Відсоток місячного плану = каса активних робочих змін / місячний план продажів × 100%.
- За 100% і більше — премія 2 000 ₴ на 15-те наступного місяця.
- Журнал каси: дата, тип зміни, каса і свій заробіток із календаря.
- Експорт та імпорт JSON працюють у кожному акаунті; імпорт **замінює його дані** після підтвердження.

## Важливо

Цей ZIP — **готовий код, а не вже запущена база**: без вашого `firebaseConfig`, увімкненого Email/Password та Firestore з установленими правилами хмарні функції не працюватимуть. У ZIP немає паролів, сервісних ключів і готових користувачів. Сторінка «Адмінпанель» не дає адміністративних прав без серверного Custom Claim.
